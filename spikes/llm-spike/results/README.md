# LLM 시험 결과 (1~7차)

Python 시험 스크립트(`spikes/llm-spike/run_*.py`)로 만화 대본 만드는 방법을 바꿔 가며 시험한 결과입니다.
시험한 논문은 모두 `samples/latent-diffusion-2112.10752.pdf`입니다. 자세한 분석은 `plan.md`의 "컷별 대본 생성" 항목에 있습니다.

- 파일 하나에 두 가지 형식이 있습니다. `.md`는 사람이 읽는 대본, `.json`은 단계별 원본 데이터(시도 횟수, 남은 문제 등)입니다.
- 스크립트를 다시 돌리면 결과는 이 폴더 바로 아래에 같은 이름으로 생깁니다. 보관하려면 차수 폴더로 옮겨 주세요.

| 폴더 | 날짜 | 스크립트 | 방식 | 모델 | 핵심 결과 |
| --- | --- | --- | --- | --- | --- |
| `round1/` | 10-02 | `run_spike.py` | 한 번에 4~8컷 | qwen3:8b | 4컷, 초록 요약 수준이라 너무 짧음 → 분량을 3~4쪽으로 바꿈 |
| `round2/` | 10-02 | `run_comic_spike.py` | 콘티 → 쪽별 생성 | qwen3 / exaone (맥북) | qwen3 481초·24컷, exaone 456초·19컷. exaone은 앞부분만 읽고 19컷 전부 '비유'로 표시 |
| `round3-desktop/` | 10-03 | `run_comic_spike.py` (개선판) | 쪽 범위를 코드가 나눔 + 검사·다시 쓰기 | qwen3 / exaone (데스크탑) | qwen3 409초, 27컷 전부 비유라 근거 0개. exaone 447초, 사실 컷 10개에 근거 |
| `round3-mac/` | 10-03 | 위와 같음 | 위와 같음 | qwen3 (맥북) | 1,704초. 데스크탑이 약 4배 빠름을 확인 |
| `round4/` | 10-03 | `run_outline_spike.py` | 구조도 → 핵심 사실 추출 → 대사 (근거는 코드가 붙임) | qwen3 / exaone | qwen3 262초·남은 문제 0, exaone 384초·남은 문제 8. 목차가 앞부분에 몰려 한계·결론이 빠짐 |
| `round5/` | 10-03 | `run_hybrid_spike.py` | 핵심 사실 추출은 qwen3, 대사는 exaone | qwen3 + exaone | 297초, 28컷, 남은 문제 9. 사실이 범위 앞부분에 몰림 |
| `round6/` | 10-03 | `run_chunk_spike.py` | 코드가 12조각으로 나눔, 사실 컷을 하나씩 요청 | qwen3 + exaone | 449초, 30컷, **남은 문제 0(처음)**. 구조 문제는 모두 해결 |
| `round7/` | 10-03 | `run_story_spike.py` | 기승전결 이야기 뼈대 + 섞인 단어 검사 | qwen3 + exaone | 366초, 29컷, 남은 문제 5. **사용자 평가: 괜찮음** → 이 방식을 Spring으로 옮김 |

7차 이후에는 같은 방식을 Spring 백엔드에서 실행합니다. 그 결과는 저장소 루트의 `results/` 폴더에 있습니다.
